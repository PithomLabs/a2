# ADR-0203 — Capture mechanism + translated 12-attack battery spec

Status: PROPOSED (research gate; self-approved — no reviewer available, see §8).
Date: 2026-11-10. Revised Gate A (Z#2–#4: T13 restored, separate-DB fallback, ticket disposition).

## Context

D1 stale-RR admission is live-proven (P0): RR snapshot fixes at first
statement incl. lock-acquire SELECT; writers committing during lock wait are
invisibly missed (DOCUMENTED M2 §6). Gate 2 ADR direction is RC +
transaction-scoped employer gate + claim proof-check (Option A retired),
DOCUMENTED but NOT implemented and production migration NOT authorized
(Gate 2 ADR :3). Binding Key Decision #4: research covers both XID-ticket and
transaction-scoped options; ADR decides with a translated attack battery —
pre-empting pending Gate 1 is forbidden. DBOS cannot hold business locks
across steps/crashes (DOCUMENTED Phase 3 §2): the gate must live inside ONE
`RunAsTransaction` txn on the shared-pool path.

## Decision

POC capture = Gate-2 transaction-scoped employer gate (RC) + claim
proof-check, executed inside a single DBOS `RunAsTransaction` on the shared
pool (atomic business write + durability record — DOCUMENTED Phase 3 §2),
inside workflow `capture:{runID}` (readiness step → atomic capture txn →
hash-verify step → `SetEvent("snapshot-ready")`). XID-ticket mechanism stays
retired (already unwired; DOCUMENTED `admission.go:1-10`). This decides the
POC mechanism only; the production Gate 1 ruling remains HUMAN and pending.

Ticket-vs-gate disposition (finding #4, PROPOSED pending R5 confirmation): no
head-to-head bake-off. Prior Gate-2 authority (Option A retired after live
attacks proved ordering-only semantics + unrestorable barrier loss —
DOCUMENTED Gate 2 ADR) plus refusal-to-resurrect satisfies binding Key
Decision #4. If R5 demands the bake-off, run both mechanisms on disposable
DBs (~1 day) before Gate B stage B2.

## Alternatives considered

1. Keep RR + advisory-lock capture — REJECTED: D1 live-proven (DOCUMENTED).
2. XID-ticket admission — REJECTED for POC: retired by Gate 2 ADR, unwired;
   resurrecting pre-empts Gate 1.
3. Capture as ordinary `RunAsStep` — REJECTED: step body outside any txn;
   crash between effect and checkpoint re-executes (DOCUMENTED at-least-once).
4. Separate-DB DBOS placement for capture — REJECTED for capture: two-txn
   split replaces atomicity with replay; capture needs the atomic path
   (DOCUMENTED Phase 3 §2). (Placement generally: see DECISION-REQUESTS R6.)

## Separate-DB fallback battery variant (finding #3, DESIGNED not built)

If R6 ever goes separate-DB, atomic capture collapses to replay semantics
(txn1 user commit + txn2 checkpoint; crash window closed by replay, `fn` must
be deterministic — DOCUMENTED Phase 3 §2). The battery then changes shape:
T1–T8 assert replay-adoption (loser's committed write adopted once, never
re-executed); kill -9 inside "capture" splits into pre-txn1-commit (zero
partial rows) and between-txn1-and-txn2 (layer-2 replay, `fn` invocation
counter stays 1); T12 close-race keeps its guarantee via the gate txn on the
user DB. The POC executes the shared-pool battery unless R6 says otherwise.

deterministic interleavings via `dbutil` race-pool pattern + writer-first
coverage (closing D6-P2c); each test asserts persisted state, not just error
codes; three time zones per binding validation plan.
