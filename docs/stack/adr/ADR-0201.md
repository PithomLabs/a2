# ADR-0201 — Stack supersede: PG 18.6 + DBOS + immudb as the POC stack

Status: PROPOSED (research gate; self-approved — no reviewer available, see §7).
Date: 2026-11-10. Scope: synthetic POC on disposable DBs only; production
migration NOT authorized (DOCUMENTED Gate 2 ADR :3).

## Context

The current stack (PG16 + hand-rolled advisory-lock capture + plain-table
audit) has live-proven defect classes: D1 stale-RR admission (P0), seven P1
barrier gaps, EF-E3 snapshot fabrication (P0), EF-F1A/B direct/vacuous
validation (P1) (DOCUMENTED M2 review §6–8; Phase 1 writer matrix). Capture→
validate is two ad-hoc txs with ambiguous crash state; nothing external
anchors snapshot hashes (Phase 1 gaps 1–2). PG 16 EOL 2028-11-09; PG 18 EOL
2030-11-14 (DOCUMENTED versioning page).

## Decision

Adopt all three for the POC, with the [ownership allocation](../PATTERNS.md#3-ownership-table):
PG 18.6 = operational truth (fresh cluster + migrate + reload); DBOS Transact
Go = durable execution (shared-pool same-DB `dbos` schema path); immudb =
provenance sidecar (standalone server, native Go SDK, hashes/digests only).
Per-technology verdicts: PG18 ADOPT-FOR-POC (conditional on E5);
DBOS ADOPT-FOR-POC (conditional on version pin + build + crash battery +
placement ruling); immudb ADOPT-FOR-POC (conditional on license + custody +
genesis + tamper battery). Full evidence: [RESEARCH.md](../RESEARCH.md) §§2–4.

## Alternatives considered

1. PG alone — REJECTED for POC: closes no crash-recovery or tamper-evidence
   gap (Phase 1 gaps 1–2 survive; INFERRED).
2. PG+DBOS — viable fallback if immudb license unacceptable; loses
   tamper-evidence, keeps durability (ASSUMPTION).
3. PG+immudb — viable fallback if DBOS SDK unfit; loses durable orchestration,
   keeps evidence (ASSUMPTION).
4. Status quo PG16 — REJECTED: M2 FAIL verdict stands; D1/EF-E3 live
   (DOCUMENTED M2 review).

## Consequences

- POC runs on digest-pinned `postgres:18.6` at `/var/lib/postgresql` volume
  (DOCUMENTED image layout); old 16 volume preserved, never reused in place.
- New failure modes: dual-write crash windows (outbox design), DBOS replay
  hazards (Patch discipline), immudb ops/licensing load — see
  [RESEARCH.md](../RESEARCH.md) §7 risks.
- AGENTS.md boundary 8 ("no second service") needs a new decision for any
  production adoption — POC on disposable DBs does not set it (ASSUMPTION:
  flagged, not ruled).

## Revisit trigger

Any stop condition fires (unviable tech, unacceptable license, threat-model
breach, frozen-file edit required) → halt with report, never workaround
(binding plan). Revisit at Phase 7 before production migration planning.

## Acceptance criteria (pinned before POC)

- [ ] E5: migrations 00001–00012 apply cleanly on 18.6; Go suite green, no

- [ ] DBOS version pinned; scratch `go mod` + build proves pgx MVS interop.

- [ ] `task build && task test && task lint` green; DB-gated tests run.
