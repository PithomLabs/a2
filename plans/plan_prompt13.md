## Approach

Treat this as one schema-plus-service change with the database as the enforcement authority and Go as the ergonomic path — never the reverse. The three load-bearing design decisions, all grounded in the current code:

**1. D-RACE: shared advisory lock plus a commit-order sequence, not timestamps.**
`AddCompensation` ([hr.go](/home/chaschel/Documents/go/a1/internal/hr/hr.go:475)) and `transition()` approval ([timesheet.go](/home/chaschel/Documents/go/a1/internal/timesheet/timesheet.go:734)) both stamp `now()` (transaction-start), so lock ordering alone cannot fix the `created_at > approved_at` comparison in `checkCompConflict` ([readiness.go](/home/chaschel/Documents/go/a1/internal/payroll/readiness.go:444)). Implement:
- One lock convention: transaction-scoped advisory lock `pay-basis:<employer-uuid>:<employee-uuid>`, acquired via a single SQL helper callable from Go, triggers, and functions (mirrors the existing `attendance:` convention in [attendance.go](/home/chaschel/Documents/go/a1/internal/attendance/attendance.go:71)).
- One ordering: `pay_basis_seq` sequence; compensation writes and approval transitions take `nextval` only after acquiring the lock, so sequence order equals commit order.
- Readiness flags a conflict when the compensation row is newer by sequence **or** by `created_at` (the latter preserves behavior for legacy backfilled rows at seq 0).
- An approval trigger assigns `basis_seq` on transition to `approved` and rejects direct writes to `basis_seq`, so raw-SQL approval cannot evade the barrier. No payroll-run approval path exists (`runs.go` has create/exclude only), so timesheet approval is the sole finalization path in scope.
- Rejected: `track_commit_timestamp` (server-config dependency, NULL edge cases) and `clock_timestamp()` (tie risk; prompt forbids timestamp-only fixes).

**2. Compensation writes move behind controlled functions.**
`compensation_line` has only a per-`terms_id` exclusion ([00004](/home/chaschel/Documents/go/a1/migrations/core/00004_protection.sql:249)), direct-SQL INSERT is unaudited (D-AUDIT), and no correction path exists (D-NOCORRECT). Since the app role cannot UPDATE history, a trigger cannot mark superseded rows and cannot distinguish service writes from raw SQL for audit purposes — so revoke app INSERT on `compensation_line` and route all writes through `SECURITY DEFINER` functions `add_compensation` / `correct_compensation`, following the `close_employment_terms` precedent ([00010](/home/chaschel/Documents/go/a1/migrations/core/00010_m12_integrity.sql:541)). The refactor surface is small (service INSERT plus 3 test files). Functions enforce containment, cross-terms same-code overlap, exact scale, the basis lock + sequence, successor marking (`supersedes_id` + `UNIQUE`, original never mutated), and one canonical audit row. Raw table INSERT becomes a 42501 fail-closed negative; semantic tests call the functions as `app`. `close_employment_terms` gains child-bounds validation (children may not outlive the close). Approved-period corrections are allowed but flagged with an explicit correction state in readiness until downstream reissue/approve — mirroring the attendance correction model rather than inventing a second approval machine.

**3. Correction groups gain a predecessor set, not a single column.**
Stage B requires one successor group for a multi-segment re-correction, which the single `predecessor_interval_id` column ([00010](/home/chaschel/Documents/go/a1/migrations/core/00010_m12_integrity.sql:98)) cannot represent. Migration `00011` adds `attendance_correction_group_predecessor(group_id, predecessor_interval_id)` with composite FKs and `UNIQUE(predecessor_interval_id)`, backfills singletons, and drops the old column. Binding generalizes cleanly: `segment.supersedes_id` ∈ the group's predecessor set (equality for first corrections). A deferred constraint trigger enforces ≥1 segment, ≥1 predecessor, same-transaction creation (via `xmin`, closing “append after close”), and sibling completeness (a re-correction predecessor set must equal the old group's full current membership — the DB backstop for group-atomicity). `Correct()` takes `interval_ids[]` (replacing `IntervalID`), rejects partial sets with a machine-readable missing-sibling error, requires the new bounds to cover the union, and `ListIntervals` surfaces `correction_group_id`.
